# ПОЛНАЯ ТЕХНИЧЕСКАЯ И АРХИТЕКТУРНАЯ СПЕЦИФИКАЦИЯ (SPEC.MD)

## 1. Дизайн-система и Визуальная концепция «Legal Boutique (Light)»

### Фоновые цвета:
- `bg-primary`: `#F8F9FA` / `#F5F5F3` (теплый алебастр/камень, убирает «больничную» белизну).
- `bg-surface`: `#FFFFFF` (карточки практик, модалки, поп-апы).
- `bg-subtle`: `#ECECE8` (разделители, тонкие границы `border-[#E2E2DC]`).

### Типографика и цвета текста:
- `text-main`: `#141517` (глубокий графит, мягче чистого `#000000`).
- `text-muted`: `#5E6267` (для подзаголовков, мета-информации и сносок).
- `font-heading`: Serif (Literata или Cormorant Garamond), полужирный / курсивные акценты.
- `font-body`: Jost (400, 500, 600).

### Акцентный цвет:
- `accent`: Тёмная платина / благородный индиго `#1E293B` с микро-акцентами приглушенной бронзы/латуни `#9B815C` (для бейджей, тонких линий при ховере).

### Кнопки (CTA):
- Всегда единый посыл: **«Обсудить ситуацию»**.
- Стиль: Скругление `rounded-none` или минимальное `rounded-[2px]`, строгая заливка `#141517` с белым текстом, либо аутлайн с инверсией и магнитной анимацией (magnetic button) на десктопе.

## 2. Реляционная модель данных (Data Model / CMS Schema)
Для масштабируемой админки и сквозной перелинковки фиксируем единую TypeScript-схему (в `types/models.ts`):

```typescript
// 1. Практика (категория верхнего уровня)
export interface Practice {
  id: string;
  slug: string; // 'criminal-defense', 'corporate-disputes'
  title: string;
  shortDescription: string;
  fullDescription: string;
  iconName: string; // SVG icon key
  services: Service[]; // Связанные услуги
  leadLawyers: Lawyer[]; // Ведущие юристы практики
  cases: Case[]; // Выигранные дела в рамках практики
}

// 2. Услуга (конкретная детальная страница)
export interface Service {
  id: string;
  slug: string;
  practiceId: string;
  title: string;
  problemStatement: string; // С какой проблемой пришел доверитель
  solutionApproach: string; // Как бюро защищает интересы
  keyAdvantages: string[];
  cases: Case[];
  responsibleLawyerId: string;
}

// 3. Команда / Адвокат
export interface Lawyer {
  id: string;
  slug: string;
  name: string;
  status: string; // Партнер, Адвокат, Руководитель практики
  specialization: string;
  photoUrl: string; // Вертикальный портрет 3:4
  experienceYears: number;
  education: string[];
  bio: string;
  practiceIds: string[];
  cases: Case[];
}

// 4. Кейс (Успешное дело)
export interface Case {
  id: string;
  slug: string;
  title: string;
  practiceId: string;
  lawyerIds: string[];
  claimAmount?: string; // Например, "1,2 млрд ₽" или "388 млн ₽"
  resultSummary: string; // Краткая суть победы для превью
  challenge: string; // Сложность ситуации
  solution: string; // Действия бюро
  courtInstance?: string;
  date: string;
}

// 5. Публикация / Блог
export interface Article {
  id: string;
  slug: string;
  title: string;
  category: string;
  previewText: string;
  content: string;
  authorId?: string;
  date: string;
}
```

## 3. Архитектура страниц и User Flow

### 3.1. Главная страница (Сводный Hub)
- **Header (Sticky / Smart Hide при скролле вниз):**
  - Логотип et.legis, Меню: Практики, Команда, Кейсы, Блог, Контакты.
  - Кнопка CTA: «Обсудить ситуацию» (вызывает Drawer / Modal с формой).
- **Hero-секция:**
  - Статусный заголовок антиквой (например: «Защита интересов бизнеса в сложных судебных и уголовных процессах»).
  - Подзаголовок: «Адвокатское бюро Etlegis. Стратегический консалтинг, снижение персональных рисков руководства и защита корпоративных активов».
  - Главная кнопка: «Обсудить ситуацию» + плавная ссылка-скролл к Практикам.
  - Фоновый визуал: минималистичный high-end интерьер переговорной/офиса с легким затемнением и параллаксом Lenis.
- **Блок доверия (Цифры):**
  - 4 ключевые метрики на белой плашке:
    - **2019** — Год основания бюро.
    - **1,2+ млрд ₽** — Сохраненных и защищенных активов доверителей.
    - **94%** — Успешно разрешенных споров в арбитраже и судах.
    - **24/7** — Оперативная поддержка при экстренных следственных действиях.
- **Секция «Практики» (Интерактивная замена услуг):**
  - Десктоп: Раскладка аккордеоном или горизонтальными карточками со сменой активного фона/иконки при наведении (GSAP hover-flip).
  - Мобильная версия: Горизонтальный плавный свайпер/карусель (Snap-scroll) карточек с индикатором прогресса и крупными зонами тапа.
  - В каждой карточке: иконка, название практики, список 3–4 ключевых услуг-ссылок и кнопка перехода на страницу практики.
- **Секция «Команда»:**
  - 3 ключевых партнера/руководителя (фото в единой ч/б или приглушенной гамме, ФИО, специализация, ссылка «Подробнее об адвокате»).
  - Кнопка: «Вся команда бюро» → `/team`.
- **Секция «Кейсы (Результаты)»:**
  - Карточки побед в стиле K&S: тег практики, жирная цифра защищенного бюджета (1,2 млрд ₽, 20 млн ₽), краткая формулировка риска и итог.
- **Секция «Блог и СМИ»:**
  - 3 последних экспертных комментария/статьи.
- **Большой статусный Футер-монолит:**
  - Качественное фото переговорной комнаты бюро в полный рост с оверлеем.
  - Встроенная форма заявки: Поля «Имя», «Телефон», «Суть вопроса (кратко)», чекбокс ПДН.
  - Кнопка: «Обсудить ситуацию».
  - Прямые каналы связи: Кликабельный номер `+7 (495) 105-91-15`, WhatsApp, Telegram, адрес офиса.

## 4. Набор автоматических тестов (TDD-валидация для Вайб-кодинга)
По принципу видео: сначала агент запускает проверки, убеждается, что они падают (Red), пишет код, и не останавливается, пока все не станут зелеными (Green).

### 4.1. Юнит- и Интеграционные тесты (Vitest / React Testing Library)
Создать файл `tests/pages.test.tsx`:
- `test_navigation_links_exist`: Проверяет, что все пункты меню (`/practices`, `/team`, `/cases`, `/blog`, `#contacts`) возвращают код 200 и не содержат `#` заглушек.
- `test_cta_buttons_label`: Проверяет, что все основные кнопки конверсии содержат точный текст «Обсудить ситуацию».
- `test_relational_integrity`: Проверяет, что у каждой практики есть связанные услуги, а у кейсов валидные `practiceId`.
- `test_lead_form_validation`: Проверяет валидацию телефона (маска РФ), обработку обязательных полей и блокировку повторной отправки.

### 4.2. E2E и Мобильные проверки (Playwright / Cypress)
Создать файл `e2e/mobile-ux.spec.ts`:
- `test_viewport_mobile_no_overflow`: На экранах 375px (iPhone SE) и 390px (iPhone 14/15) горизонтальный скролл страницы строго равен 0 (`document.documentElement.scrollWidth === window.innerWidth`).
- `test_practices_swipeable`: На мобильном вьюпорте секция практик свайпается пальцем, карточки имеют атрибуты доступности (`role="region"` / `aria-roledescription="slide"`).
- `test_smooth_scroll_integration`: Инициализирован Lenis, на body нет артефактов дергания, `useGSAP` не выдает консольных ворнингов утечки памяти.

## 5. Поэтапный план реализации (Prompting Roadmap для Anti-Gravity Agent)
Выполняйте этот план строго по шагам. Каждая ветка изолируется через Git.

### Этап 1. Инициализация и Архитектурный каркас (Branch: `feature/scaffold-core`)
- Инициализация Next.js 15+ (App Router, Tailwind CSS, TypeScript).
- Подключение `@studio-freight/lenis` (или `lenis/react`), `gsap`, `@gsap/react`.
- Настройка шрифтов в `next/font/google`: Jost и Cormorant Garamond (или Literata).
- Создание директорий: `components/ui/`, `components/sections/`, `lib/data/`, `types/`.
- Написание mock-данных на базе оригинального контента etlegis.ru.

### Этап 2. Спецификация тестов (Branch: `test/contracts`)
- Написание файлов `tests/pages.test.tsx` и `e2e/mobile-ux.spec.ts` с проверками всех ссылок, отсутствия горизонтального оверфлоу, маски формы.
- Запуск: убедиться, что тесты красные (Failed).

### Этап 3. Глобальный лейаут, Навигация и Плавный скролл (Branch: `feature/layout-lenis`)
- Компонент `SmoothScrollProvider` с хуком `useGSAP` и очисткой контекста.
- `Header`: адаптивный десктоп + бургер-меню (полноэкранный оверлей для мобайла с плавной анимацией пунктов меню).
- `Footer`: широкоформатный блок с фото переговорной, формой заявки и прямыми контактами.
- `Modal/Drawer`: всплывающее окно «Обсудить ситуацию» при клике на шапку.

### Этап 4. Секции Главной страницы (Branch: `feature/home-sections`)
- Hero + Numbers: Анимация появления заголовка и цифр через GSAP ScrollTrigger.
- Практики: Интерактивные карточки с иконками, раскрытием списка услуг и мобильным touch-свайпом.
- Команда & Кейсы: Сетки карточек со ссылками на детальные сущности.
- Запуск тестов верстки и адаптива.

### Этап 5. Внутренние шаблоны (Branch: `feature/inner-pages`)
- Шаблон `/practices/[slug]` (Практика со списком дочерних услуг и привязанным юристом).
- Шаблон `/team/[slug]` (Карточка адвоката: опыт, специализация, дела).
- Шаблон `/cases/[slug]` (Детальный разбор победы в суде).

### Этап 6. Финальная оркестрация и CI/CD (Branch: `feature/qa-and-audit`)
- Прогон всех тестов Playwright и Vitest до 100% Green.
- Lighthouse аудит (Performance > 90, SEO = 100, Mobile Accessibility = 100).
- Подключение админки к сформированной реляционной схеме данных.
